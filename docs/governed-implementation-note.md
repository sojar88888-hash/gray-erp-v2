# GRAY ERP — مذكرة التنفيذ المحكوم للنسخة الأولى

**حالة الوثيقة:** مرجع تنفيذ للنسخة الأولية.  
**تصنيف البيئة:** تنفيذ معزول ومقيّد، وليس نظام محاسبة إنتاجيًا معتمدًا.

## 1. ما تم تنفيذه

تتضمن النسخة الحالية تطبيق ويب عربيًا من اليمين إلى اليسار للوحدات الرئيسية في GRAY ERP، ونموذج بيانات منظمًا للكيانات التجارية والتشغيلية والمالية، ومسارات خادمية للمصادقة والصلاحيات، وسجل تدقيق ملحق فقط. يمكن للمستخدم المصرح له تهيئة شركة واحدة أولية، ثم إدارة بيانات العملاء والموردين والأصناف. وتُسجل عمليات الإنشاء هذه مع معرّف المستخدم والوقت والكيان في سجل التدقيق.

| المجال | الحالة الحالية | ملاحظة الحوكمة |
|---|---|---|
| الشركة ونطاق البيانات | مفعّل | تُنشأ الشركة من جلسة مصادق عليها وتُسند إلى المستخدم الحالي |
| العملاء والموردون والأصناف | مفعّل بحدود أولية | الإنشاء والقراءة محميان من الخادم ويُنشئان حدث تدقيق |
| سجل التدقيق | مفعّل للعرض والإنشاء | التطبيق لا يوفّر عملية تعديل أو حذف للأحداث |
| المخزون والحركات | نموذج البيانات والواجهة جاهزان | لا يُنفّذ إدخال أو تحويل أو تسوية فعلية بعد |
| المستندات التجارية | نموذج البيانات والواجهة جاهزان | لا توجد حاليًا دورة اعتماد أو فواتير تشغيلية فعلية |
| المحاسبة والترحيل | **محجوب** | لا إنشاء قيود أو ترحيل أو إقفال أو تقارير رسمية |

## 2. حدّ المحاسبة الصريح

لا تمثل هذه النسخة دفتر أستاذ معتمدًا ولا يجوز استخدامها لإصدار نتائج مالية رسمية. تم إنشاء جداول دليل الحسابات والفترات والقيود والأسطر لتثبيت مفردات النظام وعلاقاته المستقبلية فقط. يتطلب تفعيل أي قيد أو ترحيل اعتمادًا مسبقًا لسجل الحسابات المؤرّخ، وسياسة السنة المالية والعملات والضرائب، وقواعد الترحيل، وفصلًا مثبتًا بين الإنشاء والمراجعة والترحيل، واختبارات اتزان ومصالحة قابلة لإعادة التنفيذ.

> يظل المستند التشغيلي مصدرًا للعمل، أما الأثر المحاسبي فهو محجوب حوكميًا إلى حين اعتماد الضوابط والأدلة.

## 3. نموذج الصلاحيات وحدوده

تُطبق الصلاحيات داخل إجراءات الخادم، لا في عناصر الواجهة فقط. الأدوار الأولية هي: `admin` و`manager` و`accountant` و`user`. تتطلب إجراءات إنشاء أو قراءة العملاء والموردين والأصناف صلاحية الوحدة المقابلة، ولا تُشغّل الواجهة استعلامات البيانات الأساسية قبل اكتمال التحقق من الصلاحية. لا يعني هذا أن نموذج الصلاحيات جاهز للمؤسسة النهائية؛ فما زال يحتاج إلى مصفوفة تفويض معتمدة، وربط للفروع، ومسار إدارة أدوار مستقل، وسجل موافقات لتغييرات الصلاحيات.

## 4. حدود تكامل Supabase

تم التحقق من اتصال قراءة فقط بخدمات Auth وStorage عبر عنوان المشروع والمفتاح القابل للنشر. يخزّن التطبيق بيانات اتصال الخادم ضمن أسرار بيئة التطبيق ولا يعرض المفتاح في الواجهة أو الملفات. لا يستخدم GRAY ERP مفتاح `service_role`، ولا يتجاوز سياسات RLS، ولا ينشئ مخطط قاعدة بيانات أو بيانات مالية في Supabase. قاعدة بيانات التطبيق الحالية تستخدم طبقة قاعدة البيانات الخاضعة لإدارة المشروع؛ ويتطلب نقل بيانات GRAY ERP إلى Supabase تصميم ترحيل منفصل، وسياسات RLS، واختبارات عزل المستأجرين، وهوية مالك مشروع مثبتة.

## 5. معايير الانتقال إلى إنتاج مالي

لا ينتقل النظام إلى إنتاج مالي إلا بعد استكمال البنود الآتية وتوثيق أدلتها:

1. اعتماد هوية الكيان القانوني والمالك المسؤول والسياسات المحاسبية والضريبية.
2. توثيق واعتماد دليل الحسابات وإصداراته وسياسات التغيير والفترات المالية.
3. تصميم إجراءات الموافقات وفصل الواجبات بين المنشئ والمراجع والمرحل.
4. تنفيذ قواعد ترحيل قابلة للتتبع، مع اختبارات توازن القيد ومصالحة الدفتر وتقارير الإقفال.
5. مراجعة الصلاحيات على مستوى الشركة والفرع، واختبار رفض الوصول وحماية السجل.
6. إعداد نسخ احتياطية وتشغيل مراقَب وسجلات أخطاء وتنبيه وإجراءات استعادة مثبتة.
7. مراجعة أمنية مستقلة لتدفق البيانات والأسرار والتكاملات الخارجية قبل تشغيل بيانات حقيقية.

## 6. قرار الجاهزية

النسخة الحالية مناسبة لاستكمال التهيئة المؤسسية وتقييم تجربة المستخدم ومسارات البيانات الأساسية ضمن بيئة مضبوطة. وهي **غير جاهزة لترحيل مالي أو لإصدار تقارير محاسبية رسمية** إلى أن تتحقق معايير القسم الخامس وتُسجل الموافقات والدلائل اللازمة.
