# قائمة ما قبل التشغيل — GRAY ERP

**الإصدار المرجعي:** التشغيل الإداري والتجاري المقيد قبل الإطلاق المالي  
**الحالة:** `PRE-GO-LIVE / NON-FINANCIAL OPERATIONS ONLY`  
**مالك المراجعة:** مدير النظام، مالك العملية، ومسؤول الحوكمة

> لا تمثل هذه القائمة تفويضًا للترحيل المحاسبي أو الاعتماد المالي أو إصدار القوائم الرسمية. وهي تضبط إطلاق النطاق التشغيلي المتاح فقط، وتبقى بوابات الجاهزية المالية مستقلة وحاجبة.

## قرار التشغيل المقترح

يمكن إطلاق النظام للاستخدام الإداري والتجاري المقيد بعد استكمال عناصر القسم الأول وتوثيق مالكيها. يغطي هذا النطاق تهيئة الشركة والفروع، البيانات الأساسية، المستندات التجارية متعددة البنود، القرارات التشغيلية، حركات المخزون المقيدة، مسودات النقد غير المرحلة، الطباعة الحية، والتقارير التشغيلية. لا يغير هذا القرار أي رصيد أو دفتر أستاذ أو مركز مالي.

| نطاق الإطلاق | القرار | الحد الحاكم |
|---|---|---|
| تهيئة الشركة والفروع والبيانات الأساسية | مسموح بعد إكمال البيانات الفعلية | جميع عمليات الإنشاء مقيدة بالدور ومسجلة في التدقيق. |
| المستندات التجارية | مسموح كدورة تشغيلية | قرار الحالة ليس اعتمادًا ماليًا ولا ينتج تحصيلًا أو قيدًا. |
| المخزون | مسموح بحركات غير مالية مقيدة | التحويل اليدوي فقط؛ الإدخال والإخراج من مستند معتمد تشغيليًا أو من تسوية جرد مدققة. |
| النقد | مسموح كمسودات قبض وصرف | لا تغير المسودة رصيدًا ولا تنشئ تسوية أو قيدًا أو سندًا ماليًا معتمدًا. |
| الطباعة والتقارير | مسموح من البيانات الحية | يسجل أثر طباعة ولا يوسم المخرج كمستند مالي رسمي. |
| الاعتماد المالي، GL، الإقفال، القوائم | غير مسموح | تبقى محجوبة إلى حين إغلاق PRE-01..PRE-08 وC.1 بأدلة معتمدة. |

## عناصر الإكمال قبل فتح الاستخدام التشغيلي

ينفذ مدير النظام هذه العناصر في بيئة الإنتاج قبل دعوة المستخدمين التشغيليين. يجب حفظ نتيجة كل بند في سجل تشغيل داخلي أو في نظام إدارة التغيير الخاص بالمؤسسة؛ لا تعتمد قائمة موقعة ورقيًا وحدها كدليل لتفعيل سلطة مالية مستقبلًا.

| # | عنصر التحقق | المالك | معيار القبول | الحالة عند تسليم الإصدار |
|---:|---|---|---|---|
| 1 | تهيئة الشركة | مدير النظام | اسم الشركة، العملة الافتراضية، وسياسة التشغيل الأساسية محفوظة. | يتطلب تنفيذ العميل |
| 2 | إعداد الفروع | مدير النظام | يوجد فرع واحد فعّال على الأقل لكل نطاق تشغيلي مقصود. | يتطلب تنفيذ العميل |
| 3 | المستخدمون والأدوار | مدير النظام | تعيين الأدوار الأدنى اللازمة، والتحقق من عدم تخفيض الحساب الإداري الحالي. | يتطلب تنفيذ العميل |
| 4 | البيانات الأساسية | مالك المبيعات/المشتريات/المخزون | إدخال العملاء والموردين والأصناف والحسابات النقدية والمواقع الفعلية. | يتطلب تنفيذ العميل |
| 5 | تسلسل المستندات | مالك العملية | اختبار إنشاء مسودة متعددة البنود، إرسالها للمراجعة، واتخاذ قرار تشغيلي بواسطة مستخدم مختلف. | متاح للاختبار |
| 6 | ضبط المخزون | مسؤول المخزون | اختبار تحويل مادي، حركة مرتبطة بمستند معتمد تشغيليًا، وتسوية جرد بمراجع فعلية. | متاح للاختبار |
| 7 | مسودات النقد | مسؤول الخزينة | اختبار مسودة قبض ومسودة صرف مرتبطة بحساب وفرع وطرف فعليين دون تغيير رصيد. | متاح للاختبار |
| 8 | المطبوعات الحية | مالك العملية | فتح نسخة حية من مستند أو مسودة نقد، ثم حفظ PDF عبر المتصفح مع التأكد من التحذير غير المالي. | متاح للاختبار |
| 9 | سجل التدقيق | مسؤول الحوكمة | مراجعة أحداث الإنشاء والقرار والتصدير والتأكد من عدم وجود تعديل أو حذف في الواجهة. | متاح للاختبار |
| 10 | الاسترداد والدعم | مدير النظام | تحديد مالك الدعم، سياسة كلمات المرور، ومسار معالجة الحوادث قبل دعوة المستخدمين. | يتطلب إجراء مؤسسي |

## اختبارات قبول التشغيل

يجب تنفيذ سيناريو واحد على الأقل لكل مسار أدناه باستخدام بيانات اختبار يملكها العميل أو بيانات تشغيل فعلية مصرح بها. لا تستخدم بيانات اختلاقية لتمثيل عملاء أو أرصدة أو نتائج مالية. تحكم الصلاحيات الخادمية المسارات، وتتحقق الاختبارات البرمجية من الرفض قبل الوصول إلى البيانات للمستخدم غير المخول.

| السيناريو | النتيجة المقبولة | الأثر المتوقع |
|---|---|---|
| مستخدم غير مخول يحاول قراءة عميل أو مخزون أو مسودة نقد | يرفض الخادم الطلب بصلاحية واضحة. | لا قراءة للبيانات ولا إنشاء حدث تجاري. |
| صانع مستند يحاول اعتماد مستنده بعد المراجعة | يرفض انتقال الحالة النهائي. | يبقى فصل صانع المستند عن صاحب القرار التشغيلي. |
| مسؤول المخزون ينشئ إدخالًا أو إخراجًا يدويًا | يرفض النظام الإدخال الحر. | تقصر الحركة على المصدر التشغيلي أو الجرد؛ التحويل المادي فقط يدويًا. |
| مستخدم مخول ينشئ مسودة نقد | تحفظ المسودة كـغير مرحلة. | لا رصيد ولا حركة بنك ولا قيد دفتر أستاذ. |
| مستخدم مخول يطبع مستندًا أو مسودة | تفتح النسخة الحية ويسجل أثر الطباعة. | لا اعتماد مالي ولا تعديل للحالة. |
| مستخدم يفتح تقريرًا تشغيليًا | تظهر مؤشرات حية أو حالة فارغة صريحة. | لا ميزان مراجعة ولا أرباح وخسائر ولا مركز مالي رسمي. |

## حدود حظر لا يجوز تجاوزها

لا يجوز تحويل أي قرار تشغيلي، زر طباعة، مسودة نقد، أو حركة مخزون إلى **اعتماد مالي** أو **قيد دفتر أستاذ**. كما لا يجوز استخدام مخرجات الطباعة الحية كوثائق رسمية للتحصيل أو الإقرار أو إثبات الرصيد. تظل التسوية البنكية، الترحيل، الإقفال، موازنات المراجعة، القوائم المالية، الرواتب، الإهلاك، والضرائب خارج نطاق التشغيل المسموح بهذا الإصدار.
